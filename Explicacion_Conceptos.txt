1. ARREGLO SIMPLE Y ARRAYLIST
Para los meses usé un arreglo simple de tipo String llamado MESES que tiene los 12 meses del año ya guardados. Como la cantidad de meses no cambia, el arreglo es de tamaño fijo y, para mostrar el mes que pide el usuario, utilizo el índice MESES[numeroMes - 1].
Para los trabajadores usé una colección ArrayList llamada nomina. Elegí ArrayList porque la cantidad de empleados no es fija y puede ir aumentando conforme se registran. Para guardar cada empleado usé el método add() y, para saber cuántos empleados llevo registrados, usé el método size(). Para mostrar la lista completa en el reporte, recorrí el ArrayList utilizando un ciclo for de tipo for-each.

2. CLASE ABSTRACTA Y MÉTODOS ABSTRACTOS
Creé la clase Empleado como una clase abstracta porque representa la base de cualquier trabajador, pero no se debe instanciar directamente con new Empleado. En esta clase declaré los métodos abstractos calcularPago() y obtenerTipo(), para obligar a que las clases hijas definan su propia lógica de cálculo y su tipo.

3. HERENCIA Y SOBREESCRITURA (@OVERRIDE)
Las clases EmpleadoFijo y EmpleadoPorHora heredan de la clase base Empleado usando la palabra extends. Ambas subclases utilizan la anotación @Override para sobreescribir los métodos calcularPago() y obtenerTipo(). Por ejemplo, EmpleadoFijo calcula el pago sumando el sueldo más la bonificación, mientras que EmpleadoPorHora multiplica el pago por hora por las horas trabajadas.

4. POLIMORFISMO
En el programa guardo los dos tipos de empleados (fijos y por hora) dentro de la misma lista ArrayList de tipo Empleado. Cuando imprimo el reporte de la nómina, recorro la lista y llamo al método calcularPago() de cada objeto. Gracias al polimorfismo, Java reconoce automáticamente qué fórmula ejecutar según el tipo de empleado que sea, sin necesidad de usar condiciones como if, switch o instanceof para decidir el cálculo.

5. ENCAPSULAMIENTO Y ACCESO
Todos los atributos de las clases (dpi, nombre, sueldoMensual, bonificacion, pagoPorHora y horasTrabajadas) los declaré como private para proteger los datos y evitar que se modifiquen directamente desde fuera. Para consultar la información desde otras clases usé métodos de acceso getters como getDpi() y getNombre().

6. CONSTRUCTORES, PARÁMETROS Y ARGUMENTOS
En cada clase creé constructores con parámetros para recibir los datos iniciales al momento de crear el objeto.
- Parámetro: Es la variable declarada en la definición del constructor, por ejemplo "String dpi" en la clase Empleado.
- Argumento: Es el valor real que le paso cuando instancio el objeto con new, por ejemplo el número "1234567890101" ingresado por el usuario.
Dentro de los constructores usé la palabra this para diferenciar los atributos de la clase de los parámetros que reciben el mismo nombre, por ejemplo this.nombre = nombre. Además, en las clases hijas usé super(dpi, nombre) para enviarle los datos comunes al constructor de la clase padre Empleado.

7. ÁMBITO Y ALCANCE DE VARIABLES
En el código apliqué diferentes niveles de variables:
- Atributo: La variable nomina de tipo ArrayList declarada a nivel de clase en Main, la cual se puede utilizar en todos los métodos de esa clase.
- Parámetro: La variable mensaje en el método capturarDoublePositivo(String mensaje), la cual solo existe dentro de ese método mientras se ejecuta.
- Variable local: La variable totalNomina declarada dentro del método imprimirNomina(), la cual solo existe durante la ejecución de ese bloque de código y desaparece al terminar.

Realicé la comprobación requerida en la guía con los siguientes datos:
